对一个博客来说，编辑器里的体验和浏览器里的体验应该尽可能连贯。Markdown 恰好在这两者之间搭了一座很轻的桥。

## 结构先于装饰

标题建立层次，列表组织步骤，引用强调一个值得停顿的想法。它们先是内容的结构，然后才是视觉样式。

```md
## 一个清晰的小节

这里是正文。

- 第一个步骤
- 第二个步骤

> 留一点空间，让想法被看见。
```

我喜欢在写作时尽量不考虑样式。等内容结构清楚了，再让阅读界面帮助它变得更容易被理解。

## 为代码留出舒服的位置

技术文章的代码块需要考虑换行、横向滚动、主题颜色和复制操作。正文里的行内代码，也应该足够明显而不突兀。

这些设计的目的不是让代码看起来更复杂，而是让读者能把注意力放在它真正表达的东西上。

## 当文字需要一点交互

如果一个概念用文字很难说清楚，就可以使用 MDX 在文章里放入一个小实验。

```mdx
import Playground from '../../components/Playground.astro';

## 亲手试一试

<Playground />
```

交互不是每篇文章的必选项。只有在它能帮助建立直觉时，才值得付出额外的加载和维护成本。

## 最朴素的格式，最持久的内容

纯文本不依赖某个编辑器，也不必绑定某个服务。多年以后，我依然可以打开这些文件，读到当时想记录的东西。

这份可迁移性，让写作多了一点安心。
